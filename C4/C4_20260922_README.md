## Re-run the gamma x seed experiment from GitHub

This is a fresh-run recipe for a Linux machine with an NVIDIA GPU (the recorded runs used Sapelo L40S GPUs). It creates **new** parents, forks, three-cycle continuations, and H20 perturbation responses. It does not reuse the September 2026 Slurm job IDs. The published compact archive contains code and summaries, **not** the raw parent checkpoints or the CIFAR-100-C images. Do not run the historical `full.sbatch`, `run_cell.py`, or grid array script directly from a fresh clone: they have fixed Sapelo paths and expect the original jobs' checkpoints.

Access to the private repository is required. If your GitHub SSH key is already authorized, run:

```bash

cd RSI2RSD/C4
```

Alternatively, use the HTTPS clone URL with your normal GitHub authentication. Keep all outputs in a new `runs/` directory; do not commit datasets, checkpoints, or outputs to Git.

`prepare_data.py` downloads the public CIFAR-100-C archive from Zenodo (about 2.9 GB), checks its published MD5, and extracts `data/CIFAR-100-C/`. ### Run one cell

Here `gamma` is the scalar source/EMA mixing weight lambda, and `beta` is the EMA teacher refresh rate. The full matrix is `gamma in {0, 0.5, 1}` x `beta in {0.001, 0.01}` x `seed in {202, 303, 404}`: **18 cells**, with training seeds reused across parameter settings for paired comparisons. Run the commands from `RSI2RSD/C4` with the environment activated. For example, `(gamma=1, beta=0.001, seed=202)`:

```bash
gamma=1; beta=0.001; seed=202
cell="runs/g${gamma}_b${beta}_s${seed}"
mkdir -p "$cell"
python -u c4.py --data data/CIFAR-100-C --output "$cell/parent" \
  --gamma "$gamma" --beta "$beta" --seed "$seed" --cycles 1
```

Check `"$cell/parent/status.json"`. Only a `complete` parent with all 15 `block_*/attempt_*/complete.json` markers can be extended. If the parent terminates with nonfinite loss, **retain its failure trace and stop that cell**; later quantities are unavailable. Six of the original 18 cells failed this way. Do not turn such failures into zero-valued outcomes or silently rerun with changed parameters.

For a complete parent, continue with the two preselected blocks and both fork horizons, then extend the parent from block 15 to three cycles and measure the H20 responses:

```bash
for block in 5 15; do
  for horizon in 94 1410; do
    fork="$cell/fork_b${block}_h${horizon}"
    python -u run_measured_fork.py "$fork" --parent "$cell/parent" \
      --data data/CIFAR-100-C --after-block "$block" \
      --horizon "$horizon" --output "$fork"
    python verify_forks.py "$fork"
  done
done

python -u dynamics_v1/extend_trajectory.py --data data/CIFAR-100-C \
  --resume-parent "$cell/parent" --output "$cell/extension" \
  --gamma "$gamma" --beta "$beta" --seed "$seed" --cycles 3

for block in 5 15; do
  response="$cell/dynamics_b${block}"
  python -u dynamics_v1/run_dynamics.py --parent "$cell/parent" \
    --output "$response" --block "$block" --horizon 20
  python dynamics_v1/analyze_dynamics.py "$response"
done
python dynamics_v1/verify_cell.py "$cell"
```

Use a fresh output directory for every attempt; these programs reject an existing response directory. One cell uses one GPU at a time. For multiple GPUs, launch different cells in separate processes with distinct `CUDA_VISIBLE_DEVICES` values and output directories. The original 202/303 runs preceded 404, but this order does not change a cell's definition. To cover all 18, repeat the one-cell commands for every combination above; do not use seed 101 as an independent confirmation run.

For a copyable **full-matrix** command, create a one-cell driver from the same commands. This script verifies that the parent is complete before starting dependent work:

```bash
cat > run_one_cell.sh <<'SH'
#!/usr/bin/env bash
set -euo pipefail
gamma="$1"; beta="$2"; seed="$3"
cell="runs/g${gamma}_b${beta}_s${seed}"
mkdir -p "$cell"
python -u c4.py --data data/CIFAR-100-C --output "$cell/parent" \
  --gamma "$gamma" --beta "$beta" --seed "$seed" --cycles 1
python - "$cell/parent" <<'PY'
import json, pathlib, sys
p = pathlib.Path(sys.argv[1])
assert json.loads((p / 'status.json').read_text())['status'] == 'complete'
assert all(len(list((p / f'block_{i:03d}').glob('attempt_*/complete.json'))) == 1
           for i in range(15)), 'incomplete parent blocks'
PY
for block in 5 15; do
  for horizon in 94 1410; do
    fork="$cell/fork_b${block}_h${horizon}"
    python -u run_measured_fork.py "$fork" --parent "$cell/parent" \
      --data data/CIFAR-100-C --after-block "$block" \
      --horizon "$horizon" --output "$fork"
    python verify_forks.py "$fork"
  done
done
python -u dynamics_v1/extend_trajectory.py --data data/CIFAR-100-C \
  --resume-parent "$cell/parent" --output "$cell/extension" \
  --gamma "$gamma" --beta "$beta" --seed "$seed" --cycles 3
for block in 5 15; do
  response="$cell/dynamics_b${block}"
  python -u dynamics_v1/run_dynamics.py --parent "$cell/parent" \
    --output "$response" --block "$block" --horizon 20
  python dynamics_v1/analyze_dynamics.py "$response"
done
python dynamics_v1/verify_cell.py "$cell"
SH
```

For just one cell, run `bash run_one_cell.sh 1 0.001 202`. To execute the entire matrix sequentially on one GPU, run the following loop. It records failed cells and proceeds; it never changes a parameter to rescue a failure:

```bash
for gamma in 0 0.5 1; do
  for beta in 0.001 0.01; do
    for seed in 202 303 404; do
      bash run_one_cell.sh "$gamma" "$beta" "$seed" \
        > "runs_g${gamma}_b${beta}_s${seed}.log" 2>&1 || \
        printf 'FAILED or incomplete: gamma=%s beta=%s seed=%s\n' "$gamma" "$beta" "$seed"
    done
  done
done
```

Do not infer scientific completion from the loop's exit code; inspect each cell's status files and completion markers. This serial loop can be long, especially for H1410 and H20, and needs ample GPU scratch space. On a cluster, schedule independent cell scripts as separate GPU jobs instead of launching the serial loop on a login node.

### What to inspect and what this does not reconstruct automatically

- `parent/` plus `extension/` give the 45-block, three-cycle trajectory. The extension starts at block 15, so concatenate parent blocks 0-14 with extension blocks 15-44; do not count the first cycle twice.
- `fork_b{5,15}_h{94,1410}/comparison.json` contains the fixed-Q closed/replay contrasts. Keep both predetermined parents and all signs, including null or improving ones.
- `dynamics_b{5,15}/responses.json` and `dynamics_analysis.json` contain empirical state responses and the identification diagnostics. `verify_cell.py` checks hashes of **existing** manifests only; also inspect each component's status and expected count before declaring the cell complete.
- The published 32-page PDF and eleven aggregate CSV tables were assembled from the original batch's verified outputs. The commands here generate raw per-cell evidence; they do **not** automatically recreate that PDF or establish an identified Jacobian. In the original batch the four-coordinate Jacobian was not identified, and the findings were mixed.
